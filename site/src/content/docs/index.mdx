## Eight boards, four different machines

Control4's controller line looks like a product family. It isn't. Underneath
the identical black cases are four unrelated computers with four unrelated
boot chains, and each one had to be opened on its own terms.

<CardGrid>
  <Card title="EA-1 / EA-3" icon="seti:powershell">
    Intel Atom **CE5310**, i686, booting Intel **CEFDK** out of SPI-NOR with a
    kernel in a raw eMMC container. A companion TM4C microcontroller owns the
    IR and serial jacks. The EA-3's secure-boot fuse is blown, and it's taken
    over anyway.
    [EA family →](ea/)
  </Card>
  <Card title="HC-800" icon="laptop">
    Not an embedded board at all: a **small x86 PC** with a Lite-On
    motherboard, an AMI BIOS, an Atom D525 and **GRUB 0.97** reading a
    plain-text `menu.lst`. Nothing in its boot chain is signed and it needs
    zero kernel patches.
    [HC-800 →](hc800/)
  </Card>
  <Card title="CA-1" icon="setting">
    Freescale **i.MX6 SoloLite** with stock U-Boot in SPI-NOR. High Assurance
    Boot is open, the console is password-locked, and the way in is a
    `boot.scr` the vendor's own `bootcmd` already looks for.
    [CA-1 →](ca1/)
  </Card>
  <Card title="IO Extender V1" icon="puzzle">
    TI DaVinci **DM355** — an ARMv5 SoC mainline deleted in 6.2. Four files were
    resurrected from git history to bring it back, and it now boots Linux 7.1.8
    with all eight relays clicking.
    [IO Extender →](iox/)
  </Card>
</CardGrid>

## What the project actually is

openHC builds a modern kernel and root filesystem from source with Buildroot,
and installs them on hardware whose vendor never intended that. Two things fall
out of that goal and shape everything else:

- **No vendor code is redistributed.** Interfaces were learned by reading live
  units and Control4's published GPL sources; the implementations are ours.
- **Nothing irreversible, ever, if it can be avoided.** Every board has a
  documented path back to stock, and the netboot loops used during bring-up
  write no flash at all.

<Aside type="note" title="Measured, inferred, or unproven">
Almost every page here distinguishes what was **read off silicon** from what was
**derived from firmware** from what is still a **guess**. That distinction is the
most valuable thing in this repository — a plausible-looking wrong number costs
days. Where something is unverified, it says so.
</Aside>
